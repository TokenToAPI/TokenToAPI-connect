# v0.1.3 macOS release preparation

Status: local candidate. Nothing in this document means a tag, GitHub release,
platform deployment, or another person's Mac has already been validated.
The first v0.1.3 validation is macOS only. Windows work follows acceptance
by Kendrick and YC on their own Macs.

## Draft GitHub release notes

Title: `v0.1.3 — Import to Connect (macOS)`

Import an API key from TokenToAPI without copying its key or gateway into the
app. Choose **Import to Connect** on the platform, open Connect from the
browser prompt, review the fetched models, then click **Import**.

- Opens Connect whether it is closed or already running.
- Keeps permanent API keys out of app-opening URLs; setup links expire after
  two minutes and can be used only once. Retry prepares a fresh link.
- Offers the clients permitted by the key's group, including mixed groups
  and Claude Code-only restrictions.
- Reviews unfamiliar platforms and differing gateway destinations before
  fetching models. Configuration changes still require the final Import.
- Queues incoming setup while restoring configuration, and retains the
  imported gateway name in the success message.
- Gives the gateway, **Use original config**, and **Add another gateway**
  cards consistent spacing on the home page.

This release candidate supports **macOS 12+ on Apple Silicon (arm64)**.
It does not add Intel Mac support. The app is ad-hoc signed and has not been
Developer ID notarized. No Windows v0.1.3 package has been validated or prepared.
The platform update is required: v0.1.2 cannot receive the new handoff.

After import, fully quit and reopen the target client and start a new local
session. Available models and successful inference depend on your key's group
and the gateway. Local fixture checks verify configuration writes and restore;
Kendrick and YC must also verify a real request on their own Macs.

## Source and publication checklist

1. Review and commit the remaining changes on `feat/connect-import` in the
   Connect worktree. Existing implementation commits are already local.
2. Push the feature branch and merge it into `main` using your normal review
   process. Do the corresponding platform branch review against `master`.
3. Build the final package from the committed Connect source:
   `pnpm install --frozen-lockfile`, `pnpm test:ui`, `pnpm test:lifecycle`,
   `pnpm test:core`, `pnpm build:macos`. Record the source commit and checks
   in `VERIFICATION.md` and the GitHub release description.
4. Publish a macOS prerelease with the draft notes and both assets. Verify
   the download checksum and the app version before giving it to YC.
5. Deploy the matching platform backend and frontend through its existing
   managed-release runbook. Publishing a ZIP or merging source does not
   deploy the platform. Verify the download link before enabling the pilot.
6. Complete [the Mac acceptance checklist](../testing/macos-acceptance.md)
   separately on Kendrick's and YC's Macs. Record versions and results.
7. After both Mac results are saved, remind Kendrick to request the
   [recorded local/Docker cleanup](../testing/post-macos-cleanup.md).
8. Begin Windows implementation/package validation only after both Mac
   results pass. Windows platform download links must not be presented as
   available until the corresponding package exists and has been validated.

No push, merge, tag, publication, or deployment is performed by preparing
these notes. The repository owner performs those steps.
