## Release notes

Title: `TokenToAPI Connect v0.1.3`

## Platform imports

- Import API keys directly from TokenToAPI with **Import to Connect**.
- Opens the app whether it is closed or already running, fills the gateway and compatible clients, and fetches available models before import.
- Setup links are single-use and expire after two minutes; permanent API keys stay out of app-opening URLs.
- Unfamiliar platforms and gateway destinations require review before setup continues.
- Incoming imports wait until configuration restore review is complete.

## Interface

- The gateway, **Use original config**, and **Add another gateway** cards now have consistent spacing.
- The completion screen retains the imported gateway name.

## Downloads

- macOS 12+ on Apple Silicon: `TokenToAPI-Connect-0.1.3-macOS-arm64.zip`
- Verify downloads with `SHA256SUMS.txt`.

This prerelease is macOS only; the Windows package follows macOS validation. The macOS app uses an ad-hoc signature and has not been notarized.

Platform imports require the matching TokenToAPI platform update, which has not yet been deployed. After importing, fully quit and reopen the target client and start a new session.

## Source and publication checklist

1. Review and commit the remaining changes on `feat/connect-import` in the
   Connect worktree. Existing implementation commits are already local.
2. Push the feature branch and merge it into `main` using your normal review
   process. Do the corresponding platform branch review against `master`.
3. Build the final package from the committed Connect source:
   `pnpm install --frozen-lockfile`, `pnpm test:ui`, `pnpm test:lifecycle`,
   `pnpm test:core`, `pnpm build:macos`. Record the source commit and checks
   in `VERIFICATION.md` and the GitHub release description.
4. Publish a macOS prerelease with the draft notes and both assets. Verify
   the download checksum and the app version before giving it to YC.
5. Deploy the matching platform backend and frontend through its existing
   managed-release runbook. Publishing a ZIP or merging source does not
   deploy the platform. Verify the download link before enabling the pilot.
6. Complete [the Mac acceptance checklist](../testing/macos-acceptance.md)
   separately on Kendrick's and YC's Macs. Record versions and results.
7. After both Mac results are saved, remind Kendrick to request the
   [recorded local/Docker cleanup](../testing/post-macos-cleanup.md).
8. Begin Windows implementation/package validation only after both Mac
   results pass. Windows platform download links must not be presented as
   available until the corresponding package exists and has been validated.

The checklist above records the release procedure. Connect publication is complete; platform rollout and both live Mac acceptance results remain pending.
